## 二、方法

- **样本**：五组。A–D 是「是否变身」×「3 层虚落后是否先扔炸弹」的 2×2；
  E 是追加上去的对照组（炸弹后等流星全落地再裂劈），用来钉死第 4 颗的来源。
- **口径**：伤害一律取 WCL 的 `unmitigatedAmount`。这批日志全部是训练假人且目标濒死，
  WCL 把 `amount` 钳成 **1**（`overkill` 远大于实际伤害），统计页看着像 1 点伤害，
  真实数值只在 `unmitigatedAmount` 里。这一点已写进 `docs/wcl-api.md`。
- **流星归因**：先把间隔 ≤700ms 的流星归为**一串**，再把整串归给它之前最近的一次消耗施放。
  不能逐颗归因 —— 灭世灾星常在炸弹按下之后才落地，会被错误地判给炸弹（第一版脚本就踩了这个坑）。
- **技能 ID**（cn 站官方中文名，`masterData.abilities` 实测）：

| ID | 名称 | 说明 |
|---|---|---|
| 1256322 | 虚落 | 层数 buff（`applybuff` / `applybuffstack` / `removebuffstack`） |
| 1256306 | 虚落流星 | 普通流星 |
| 1256617 | 灭世灾星 | 每串流星最后那颗大的（World Killer） |
| 1264130 | 流星雨 | **暗物质**（12 跳 / 6 秒） |
| 247454 / 247455 | 幽魂炸弹 | 施放 / 伤害 |

| 187827 | 恶魔变形 | 进入变身（质量加速会给 3 层虚落并重置炸弹 CD） |
| 1256667 | 大灭 | 独立的周期性伤害，**不参与**本文结论 |

## 三、2×2 + 对照组

| 组 | 变身 | 炸弹 | 那一刀裂劈的时机 | 触发流星的施放 | 普通 + 灾星 | 合计 | 流星伤害 | 暗物质 |
|---|---|---|---|---|---|---|---|---|
| **A** | 否 | 否 | — | 裂劈 @22.69s | 2 + 1 | **3** | 141,024 | 无 |
| **B** | 否 | 是 | 爆炸瞬间（+1.03s） | 裂劈 @26.02s | 3 + 1 | **4** | 193,754 | 无 |
| **C** | 是 | 否 | — | 裂劈 @18.74s | 2 + 1 | **3** | 145,087 | 12 跳 / 84,305 |
| **D** | 是 | 是 | 爆炸瞬间（+0.94s） | 裂劈 @6.25s | 3 + 1 | **4** | 178,946 | 12 跳 / 77,042 |
| **E** | 是 | 是 | **落地后 +3.31s** | **炸弹 @3.98s** | 2 + 1 | **3** | 172,559 | 12 跳 / 101,294 |

读这张表只需要看三件事：

- **横向（是否先扔炸弹）**：3 → 4，稳定 +1 颗。
- **纵向（是否变身）**：3 → 3、4 → 4，**没有变化**。变身只决定"你手上有没有 3 层"。
- **E 的对照**：同样是炸弹 + 裂劈，只是裂劈晚了 3.3 秒 → **回到 3 颗**，而且这 3 颗归给炸弹。

> ⚠ 跨组只能比**颗数**，不能比**单颗伤害**。E 的流星单颗 49,155–49,966，A/C/D 只有 40,050–42,045，
> 暗物质 E 也最高（101,294 vs C 84,305 / D 77,042）。这是增益与暴击的差异（烈焰烙印等），
> 不是机制差异。颗数是硬的，伤害量是软的。

## 四、问题 1：非变身，3 层后「炸弹接裂劈」vs「直接裂劈」

**有联动，且是三重叠加的。**

A 组（直接裂劈）@22.69s：
```
0ms      CAST  灵魂裂劈
+354ms   DMG   灵魂裂劈 31,705
+778ms   DMG   虚落流星 40,050
+1,125ms DMG   虚落流星 40,910
+1,493ms DMG   灭世灾星 60,064      ← 第 3 颗
```
B 组（炸弹接裂劈）：
```
24.99s   CAST  幽魂炸弹
26.02s   CAST  灵魂裂劈   （同一瞬间炸弹炸出 27,216）
+0ms     DMG   灵魂裂劈 17,811      ← 明显偏低
+450ms   DMG   虚落流星 42,031
+770ms   DMG   虚落流星 43,165
+770ms   DMG   虚落流星 42,232
+1,130ms DMG   灭世灾星 66,326      ← 第 4 颗
```

三个联动点：

1. **流星 +1 颗**（141,024 → 193,754，+52,730）。炸弹自己的 3 颗与裂劈多算的 1 颗
   **被合并成一串 4 颗**（对照组 E 已证明：炸弹单独结算就是 3 颗）。这是唯一"超出天赋描述"的地方。
2. **裂劈本体掉 45%**（31,705 → 17,811）。幽魂炸弹先消耗了灵魂碎片，
   裂劈能吃的碎片变少；同一场里其它裂劈都在 31,071–34,523，只有炸弹后这一发是 17,811。
3. **炸弹本身多一份本体伤害**（27,216）。

净收益：`+52,730（多一颗流星）+ 27,216（炸弹本体）− 13,894（裂劈少打）≈ +66,052`。

## 五、问题 2：变身时，同样的两组

C 组（变身 @18.29 → 裂劈 @18.74，炸弹拖到 21.21 才扔）：
- 流星 3 颗 / 145,087，与 A 组几乎一致（A 141,024）。**质量加速给满 3 层，结算方式不变。**
- 炸弹虽然晚了 2.5 秒，仍然触发了暗物质（12 跳 / 84,305，22.65→28.14s）。

D 组（变身 @4.66 → 炸弹 @5.31 → 裂劈 @6.25）：
- 流星 4 颗 / 178,946，与 B 组同构。
- 暗物质 12 跳 / 77,042（6.63→12.12s），**跳数完整**，没有被裂劈截断，
  也没有出现"炸弹的流星被暗物质顶掉"的迹象。

结论：**变身这一维不影响流星颗数**。C 与 A 的差异在噪声内（145,087 vs 141,024，约 3%）；
D 与 B 也一致（178,946 vs 193,754，约 8%，属暴击波动）。

## 六、问题 3：变身后「炸弹接裂劈」的 bug，到底成不成立

**成立。对照组 E 把触发条件钉死了。**

E 组时间线（变身 @1.43s → 炸弹 @3.98s → 等流星全落地 → 裂劈 @8.35s）：

```
3.98s   CAST  幽魂炸弹
5.04s   DMG   幽魂炸弹 48,493      ← 爆炸，距施放 +1.06s
5.04s   BUFF  虚落 applybuff
5.43s   DMG   虚落流星 49,155      ← 第 1 颗
5.82s   DMG   虚落流星 49,966      ← 第 2 颗
6.13s   DMG   灭世灾星 73,438      ← 第 3 颗（最后一颗升级）
8.35s   CAST  灵魂裂劈             ← 比最后一颗晚 2.22s（比炸弹晚 3.31s）
8.57s   DMG   灵魂裂劈 26,968      ← 0 颗流星
```

于是三种情况全部对齐：

| 做法 | 流星 | 归属 |
|---|---|---|
| 只裂劈（A / C） | 3 颗 | 裂劈 |
| 炸弹 → **爆炸瞬间**裂劈（B / D） | 4 颗 | 裂劈 |
| 炸弹 → 落地后裂劈（E） | 3 颗 | **炸弹** |

**关键结论：炸弹自己就是 3 颗，一颗不多。第 4 颗是"爆炸那一刻正在按的那一刀裂劈"带来的。**

对照 B / D 的时间点可以看得很死：

- B：炸弹 24.99 施放 → 26.02 爆炸；裂劈施放 **26.02** —— 同一帧。
- D：炸弹 5.31 施放 → 6.25 爆炸；裂劈施放 **6.25** —— 同一帧。
- E：炸弹 3.98 施放 → 5.04 爆炸；裂劈 8.35 —— 晚了 3.31 秒，什么都没有。

不成立的部分（需要澄清的传闻）：

- **不是变身导致**。A→B（非变身）同样 +1，C→D（变身）也是 +1；变身只是提供 3 层。
- **不是暗物质导致**。C 组的炸弹在流星之后才扔，暗物质照样 12 跳；E 组暗物质也 12 跳完整。
- **不是"吞流星"**。相反是多了一颗。按"3 层只够 3 颗"的参照系，4 颗是超发。

仍未定的（D 级，别当结论用）：

为什么合并结算的结果是 **4** 而不是 **6**。如果两个技能各自完整消耗同一批 3 层，应该看到 6 颗；
只多 1 颗，说明更像是**两个施放在同一帧被合并成一次结算、计数多走了 1 格**，
而不是"同一批层被消耗了两次"。这属于引擎实现细节，日志无法再往下证；
但它不影响打法结论 —— 无论内部怎么算，玩家看到的就是「多一颗」。

## 八、对打法的实际含义（「非变身期该不该打」）

**结论：该打，而且用自然节奏打 —— 炸弹之后下一刀就裂劈，不要刻意等。**

非变身组整场对比（A vs B，同一玩家、同一假人）：

| 项目 | A 只靠裂劈花 3 层 | B 炸弹 → 下一刀裂劈 | 差 |
|---|---|---|---|
| 流星 | 141,024（3 颗） | 193,754（4 颗） | **+52,730** |
| 炸弹本体 | 20,710 | 27,216 | +6,506 |
| 裂劈本体（整场 7 次合计） | 216,237 | 211,443 | −4,794 |
| 合计 | 377,971 / 31s | 432,413 / 33s | **+54,442（+7.5% / 秒）** |

两个必须说清的点：

1. **裂劈的损失是局部的，不是总量级的。** 炸弹后那一刀从 31,705 掉到 17,811（−45%），
   但整场 7 次裂劈合计只少了 4,794 —— 碎片会自然回补。
   把"那一刀掉 45%"读成"这么打每刀都掉"是错的。
2. **多的一颗不是彩票。** B 与 D 都是"炸弹 → 下一刀裂劈"的自然按法，两次都命中；
   E 是刻意等 2.2 秒才没有。炸弹爆炸前摇 0.94–1.06 秒，与一个 GCD 相当，
   所以下一刀天然落在爆炸帧上，不需要卡帧。
   > 更正：本报告上一版写"要卡 0.1 秒、当彩票看"，那是基于 B/D 两组还不够的过度解读。
   > E 组补上之后，正确结论是"自然节奏就会命中"。

什么时候**不要**这么打：

- **3 层在手、炸弹 CD 没好** → 直接裂劈花掉，别攒。攒着最大的风险是撞上变身
  （质量加速会覆盖层数），3 层直接蒸发。
- **炸弹 CD 好了、但手上 0 层** → 炸弹这时只是本体伤害，不会触发流星
  （A 组炸弹 @24.05 就是 0 层 → 0 颗流星，实测）。
- **碎片紧张**（要留护盾/回血）→ 顺序反过来：先裂劈把碎片花在流星上，再炸弹。

一句话：**非变身期照打「炸弹 → 下一刀裂劈」，收益来自多一颗流星，不来自卡帧。**

## 十二、口径修正（M+ 实战日志暴露的问题，2026-10-23）

用一份真实大秘日志 `gvD6HnCZX32mbTPA#21`（红玉新生法池，1201s）验证时发现：
**一条伤害事件 ≠ 一颗流星。**

| 场景 | 一个目标的表现 |
|---|---|
| 单目标假人（A–E 组） | 一颗流星 = 1 条事件 |
| AoE | 一颗流星命中 N 个目标 = N 条同刻事件 |
| 目标带减伤 | 一次命中被拆成 block / absorb 多条（同一毫秒、同一目标 2–4 条） |

所以引擎的计数单位改成 **撞击时刻**（同一毫秒算一次撞击），并只对**单目标串**统计消耗层数。

对 §三 表格的修正：

| 组 | 原口径（事件数） | 现口径（撞击时刻） | 说明 |
|---|---|---|---|
| A / C / E | 3 | 3 | 不变 |
| B | 4 | **3** | 4 条事件里有 2 条落在同一毫秒，被合并 |
| D | 4 | **4** | 4 个不同时刻，仍是干净的核心证据 |

结论方向不变（炸弹 → 爆炸瞬间裂劈会多一次撞击），但**「每场稳定 4 颗」应降级为「常见 4 个撞击时刻」**：
大秘里 68 串中有 41 串是 4 个时刻（60%），这才是可复现的常态。
B 组那种同毫秒重合，日志无法与「一次命中被拆行」区分，一律按一次算 —— 只低估、不虚高。

### 12.1 伤害口径

引擎统一用 `amount`（WCL 统计页口径），**不**替换成 `unmitigatedAmount`：实测两者的大小关系不稳定——
格挡行的 `amount` 反而比 `unmitigatedAmount` 大，而假人濒死行的 `amount` 被钳成 1。

被「目标濒死」钳制的日志由 `metrics.dataQuality` 标记（>30% 的伤害行被钳制时 `overkillClamped: true`）。
A 组正是这种日志（`clampedShare = 0.959`），所以 §三 表里的 141,024 等数字是**未减免口径**，
与引擎现在输出的 metrics 不可直接对比；颗数（`impacts`）不受影响。

## 十三、撤回：13.1 「炸弹紧贴变身」不是失误

**§12 之后我曾加过一条规则 `vdh.dark_matter_bomb_before_meta`，判定「炸弹在变身前 3 秒内 ⇒
暗物质被冷却卡掉」。这条规则是错的，已删除。** 玩家指出：质量加速在进入恶魔形态时会**重置幽魂炸弹冷却**。

数据核对（`gvD6HnCZX32mbTPA#21`，38 次变身）：

| 观测 | 数量 |
|---|---|
| 炸弹在 25s 内炸过，且变身 3s 内又炸一颗（证明重置生效） | **24** |
| 上一颗炸弹已 ≥25s（不需要重置） | 3 |

所以「炸弹 → 变身 → 炸弹」是**正确手法**：两颗炸弹，第二颗触发暗物质。
之前被标成「顺序问题」的 5 次，真实成因是**碎片**：

| 变身时刻 | 碎片（变身时 / +2s / +5s） |
|---|---|
| 71.6s | 0 / 1 / 2 |
| 307.7s | 0 / 5 / 6 |
| 399.1s | 0 / 1 / 2 |
| 691.9s | 0 / 0 / 0 |
| 1125.3s | 0 / 2 / 1 |

炸弹刚炸完 → 碎片 0 → 变身后凑不出可以打的那一颗 → 15 秒窗口内没有炸弹 → 暗物质空转。
这是资源决策问题（提前攒碎片 or 接受这次空转），不是按键顺序问题。

**保留的规则**只有 `vdh.dark_matter_missing`（炸弹确实打了、6 秒内却没有任何流星雨）——
它描述的是机制缺失，不指控玩家。
